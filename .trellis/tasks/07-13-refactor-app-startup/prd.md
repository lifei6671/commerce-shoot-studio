# 精简 App 并优化首屏加载

## Goal

在不改变既有 UI、交互流程和 Runtime 合同的前提下，拆分 `desktop/src/app/App.tsx`
中混杂的展示、业务编排和纯转换逻辑，并通过真实的 Vite 代码分包减少商品工作区
首屏需要解析的 JavaScript。

当前基线：

- `App.tsx` 共 4,911 行，其中 `App` 组件本体约 3,052 行。
- `npm --prefix desktop run build` 仅生成一个 540.68 kB（gzip 158.73 kB）的
  JavaScript chunk，并触发 Vite 500 kB 大 chunk 警告。

## Requirements

- 保持商品、服饰、场景、模型配置、设置、生成历史和结果图片操作的现有行为。
- 保持现有 UI 结构、视觉样式、文案、可访问名称和用户操作路径。
- 不修改公共 Runtime Port、DTO、Tauri command、数据库 schema、依赖或锁文件。
- 从 `App.tsx` 抽离具有稳定边界的纯类型、纯转换函数和工作区展示组件；不创建
  接收大量 setter/ref 的巨型抽象。
- 商品工作区仍为默认首屏；服饰、场景、模型配置、设置等非首屏工作区使用直接
  字面量 `import()` 建立懒加载边界。
- 商品配置面板切换工作区后继续保持挂载语义，不能因拆分导致内部草稿丢失。
- 启动历史恢复和未完成场景任务续跑仍在应用层按原时机执行，不得依赖历史弹窗
  是否加载或打开。
- 保留当前工作区中的用户未提交修改，尤其是 `App.test.tsx`、`PreviewCanvas.tsx`
  和下载测试；禁止整文件重写或无关格式化。
- 新增或调整最小必要测试，覆盖默认首屏与异步工作区加载；纯函数迁移由现有行为
  测试或独立单测保护。
- 生成记录弹窗默认只渲染 10 条，滚动接近底部时每次追加 10 条；切换分类筛选时
  重置为该分类前 10 条，不改变现有视觉和历史恢复语义。

## Acceptance Criteria

- [x] `App.tsx` 不再包含大段历史反序列化、结果合并和商品 Prompt 拼装纯函数，
      文件行数相对 4,911 行基线显著下降。
- [x] 工作区展示 JSX 被拆为职责明确的组件，且商品配置面板切换后状态保持行为不变。
- [x] 生产构建生成多个异步 JavaScript chunk，入口 JS 小于 540.68 kB 基线；
      非首屏工作区不再全部静态进入入口依赖图。
- [x] 商品首屏可立即显示；点击服饰、场景、模型配置和设置后，对应工作区可正常
      异步显示，加载期间使用不改变布局的轻量 fallback。
- [x] `App.test.tsx`、`BootstrappedApp.test.tsx` 及受影响 feature 测试通过。
- [x] `make frontend-build` 和 `git diff --check` 通过。
- [x] 自 review 确认没有 UI 漂移、状态丢失、历史恢复退化、敏感信息泄漏或
      非本任务 dirty-tree 改动被覆盖。
- [x] 生成记录列表首批 10 条、触底追加 10 条、筛选重置和删除补位均有组件测试覆盖。

## Out of Scope

- 不重写三个工作区的完整状态管理架构。
- 不引入新的路由库、状态管理库或 bundle 分析依赖。
- 不修改 Rust runtime、Provider 行为或真实生图流程。
- 不为追求行数进行跨模块大规模重命名或移动。
