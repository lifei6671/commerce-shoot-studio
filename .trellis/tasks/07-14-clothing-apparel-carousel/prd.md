# 商品、服饰与场景菜单右侧营销配图

## Goal

将 `desktop/src-tauri/resources/assets/` 下四张 `apparel-*.png` 图片接入服饰菜单右侧区域，以轮播方式展示；将 `product.png` 接入商品菜单右侧空状态，并将大标题从“A+ / 详情页”调整为“AI 商品”；将 `scenes.png` 接入场景菜单右侧空状态。三个入口都使用真实营销配图，同时保持现有设计 token 和核心操作路径不变。

## Background

- 用户明确指定图片来源为 `desktop/src-tauri/resources/assets/apparel-1.png` 至 `apparel-4.png`。
- 当前工作区中前三张图片已暂存，第四张图片未跟踪；这些素材属于用户现有改动，实施时必须保留。
- 本次只调整商品、服饰与场景菜单的右侧空状态展示区域，不扩大到模型、设置或生成结果页面。
- 这是新的 UI 交互，需要在实现前确认轮播行为，并补充最小前端测试。
- 四张素材都是横向 PNG：`apparel-1.png` 为 `1983×793`，其余三张为 `2172×724`；图片内部已包含标题、商品与人物结果，不需要额外叠加营销文案。
- `ClothingPreviewCanvas` 正是服饰菜单在尚无生成结果时的右侧预览区域；生成结果出现后，`App` 会切换到共享 `PreviewCanvas`，因此轮播不应进入结果态。
- 当前 `ClothingPreviewCanvas` 已渲染四个静态分页圆点，可在不改变页面结构的前提下升级为真实轮播控制。
- 图片位于 Vite 项目根目录 `desktop/` 内，可从懒加载的服饰预览组件静态导入并由前端构建产物携带，无需新增依赖、Runtime Port 或 Tauri bundle 配置。
- `product.png` 是 `1774×887` 的 2:1 横向商品详情示例图，图片内部包含主图、场景、细节和卖点说明，不需要额外叠加说明文字。
- 商品空状态由 `PreviewCanvas` 在 `detailImages.length === 0` 时渲染；生成结果态继续使用 `GeneratedDetailCanvas`，因此商品配图不能进入结果态。
- `scenes.png` 是 `2172×724` 的横向场景流程示例图，图片内部已经完整展示“参考图 → Prompt 方案 → 生成结果”，不需要额外叠加流程卡。
- 场景空状态由懒加载的 `ScenePreviewCanvas` 渲染；场景规划或生成结果出现后由 `App` 切换到对应真实面板，因此配图不能进入规划或结果状态。

## Requirements

- 服饰菜单右侧区域展示四张 `apparel-*.png` 图片。
- 图片按稳定顺序轮播，不随机打乱。
- 轮播区域复用现有服饰页的布局、圆角、色彩、阴影和间距体系，不重做页面视觉。
- 图片资源必须在 Tauri 开发与打包环境中都能正确加载。
- 轮播不得影响服饰配置、AI 规划、真实生成、历史恢复和结果画布逻辑。
- 默认从 `apparel-1.png` 开始，每 4 秒向左平滑切换一张；`apparel-4.png` 后循环回到第一张。
- 保留右侧现有标题、说明、背景和帮助按钮，只把中间示意卡替换为真实图片轮播。
- 底部四个分页圆点升级为可点击按钮；点击后立即显示目标图片，并从完整的 4 秒周期重新计时。
- 鼠标悬停在轮播区域或键盘焦点进入轮播控件时暂停自动播放，离开后恢复。
- 系统开启减少动态效果时关闭自动播放和滑动动画，但仍允许通过分页圆点手动切换。
- 分页控件使用明确的可访问名称，并向辅助技术暴露当前页状态。
- 商品菜单右侧空状态的大标题显示“AI 商品”，不再显示“A+ / 详情页”。
- 商品空状态原有手绘流程卡替换为 `product.png`，图片完整显示，不裁切其内嵌文字。
- 商品空状态保留现有背景、副标题、帮助按钮和无障碍流程摘要；不修改商品配置、生成或结果画布逻辑。
- 场景菜单右侧空状态原有三块手绘流程卡替换为 `scenes.png`，图片完整显示，不裁切其内嵌文字。
- 场景空状态保留现有“场景图片”标题、副标题和背景；不修改场景配置、Prompt 规划、真实生成或结果恢复逻辑。

## Out of Scope

- 修改四张素材本身。
- 新增第三方轮播依赖。
- 重做商品、服饰或场景菜单布局及共享设计系统。
- 修改商品、服饰或场景生成 Runtime Port、DTO、Rust 任务合同或数据库结构。
